# Maintainability & Simplicity

Optimize for maintainability rather than simply completing the current feature.

Prefer:

* Simple architecture.
* Clear responsibilities.
* Reusable existing code.
* Small cohesive files.
* Consistent naming.
* Explicit business rules.
* Minimal duplication.

Avoid:

* Premature abstraction.
* Unnecessary files.
* Large "god" components or services.
* Duplicated logic.
* Over-engineering.
* Unrelated refactoring.

Do not introduce complexity for hypothetical future requirements.

Build the simplest architecture that safely supports the current Judo Attendance & Outreach System while leaving clear paths for future growth.
